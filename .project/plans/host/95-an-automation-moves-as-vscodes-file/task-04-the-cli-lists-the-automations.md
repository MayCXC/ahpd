## Goal

`ahpd automation list` shows each automation, so a user can find the id that export takes.

## Files

- `UPDATE: packages/server/src/commands/automation.ts` - a `list` command, on the CLI as `automation list` and on HTTP as `GET /automation/list`.
- `UPDATE: packages/server/test/blueprint.test.ts` - a test of the list, or a new test file beside it if that file is the wrong place.
- `UPDATE: docs/server/REFERENCE.md` - regenerated by the docs build, not edited by hand.

## Steps

1. Read how `teams.ts` declares its list command, and declare `automation list` the same way.
2. Read the automations from the same store that export reads.
3. Show one row per automation: id, name, folder, schedule and on or off.
4. Return the same rows as JSON under `--json`.
5. Show one plain sentence when there is no automation.
6. Write a test with two automations, and a test with none.

## Validation

- `ahpd automation list` shows the id that `ahpd automation export` takes.
- `--json` gives the same rows.
- The gates pass: build, typecheck, boundary, schema and vitest.
